# 2.0.26（本地测试版）

## 游戏更新后重新应用图片 Mod

- 入口：卡片资源左侧 **Mod 管理 → 一键恢复 Mod**。即使当前 Mod 数量为零也能进入，不要求先选中卡片。
- 新制作超框、替换图片或导入包后，按游戏目录与当前 LocalData 账号保存最终 PNG 及超框登记意图。透明像素 RGB、去闪面内框遮罩和灵摆存储映射保留，不进行二次构图或拉伸。
- 恢复重新定位当前 Texture2D，使用当前 Bundle 构建临时文件并逐像素验证。旧 PathID、分辨率或 serialized file 改变不会按旧文件整包盲目覆盖。
- 超框恢复同时修补 of_card_asset，合并目标卡行并保留新版其他官方行。不会用旧整张超框表覆盖新卡登记。
- 超框表的 Bundle 路径可能随数据版本改变。写入前刷新完整卡名字典版本，按已命名卡号覆盖范围、数量和字典时间识别配套版本，并核验表的完整容器路径。旧表仍留在 LocalData 或缓存指向旧表时，也只写入配套表；已知配套版本的表未下载则停止，不退回旧表。
- 所有临时文件验证完成后，确认游戏已退出、锁定目标并重新校验资源哈希，再提交。准备阶段可取消；提交失败会回滚游戏文件及被轮换的备份。
- `_MD卡图备份/更新恢复/<时间批次>` 同时保留旧基线与本次重新应用前的资源。新的“还原所选”基线为重新应用前当前资源，不保证此前没有其他外部 Mod。
- 已生效内容不会重复写入；素材损坏或目标不可唯一定位会跳过并报告，临时文件验证失败则停止整个批次。手动“还原所选”或关闭超框登记会停用对应恢复意图。
- 恢复入口提供确认、数量、后台进度及可读错误；长内容提供完整报告文件。保持现有深色、圆角及自适应换行操作栏。
- 修复 150% 模拟缩放及长翻译时，操作栏换行后被下方列表遮住的问题；排序菜单与恢复进度窗一并核验。保存旧 Mod 时仅捕获真正修改过的图片 Bundle，不把动画／开关关联标记当成图片改动；TCG／OCG 的恢复意图独立。

## 旧版迁移与限制

旧版没有保存所有应用结果。留有 `_MD卡图素材/超框/<卡号>`、704×1024 透明原画、卡框设置及目标备份的超框会列为旧版候选，重新合成透明、透明炫彩、炫彩或普通模式，并恢复背景缩放／偏移及去内框参数。**旧版每次预览都会保存草稿，无法可靠区分最后草稿和最后应用状态**，请确认候选卡号及构图。新版优先保存已成功应用的最终 PNG，不以草稿覆盖它。

尚未被游戏覆盖的旧图片 Mod，可先用“保存现有 Mod 到恢复库”。已被覆盖且没有修改素材、恢复库或 Mod ZIP 时，只有原版备份无法推导出旧修改。不会自动将游戏更新后的新原版误存成旧 Mod。

范围是卡图、超框及工具可编辑的视觉 **Texture2D**。不包含动画、模型、材质、任意 TextAsset 或新增资源；动画仍需保存兼容版本的 ZIP 并按原入口导入。恢复不会自动写入游戏，始终要求用户确认及游戏退出。符号链接／Junction 路径仍遵循现有写入安全检查。

## 新卡自动发现及卡名更新

- 启动、选择账号后以及运行期间每 60 秒后台检测 Steam Build 与资源元数据变化，动画页、批量恢复和写入期间暂停检查。
- 卡图 CRC 身份覆盖游戏 ushort 卡号字段的完整格式范围，不再取决于发布时的卡名列表。只收录实际存在且可解析的卡图，不虚构新卡。
- 增量扫描按 Bundle 长度／修改时间保存账号独立扫描状态。未变化不重扫；更新资源刷新旧定位及尺寸而不重复加入列表。
- 卡名字典解析失败不会中断卡图发现。字典未下载的卡先用卡号显示，不捏造名称、卡型或召唤动画资格；下载完成后再补齐。
- 字典发现缓存记住非字典结果，新下载资源才重新定位。收集并合并完整版本数据组，不在第一组旧字典命中后提前停止，避免遗漏另一组的新卡或翻译。
- 原动画索引增量关联流程继续运行，不为无原生召唤演出的卡自动新增动画。

本地测试版保留旧版本，根目录 EXE 与同级 data。只在独立镜像写入及恢复测试，不改真实游戏；实际游戏显示仍需用户验证。本次未上传 GitHub，公开测试版仍为 2.0.23。

# 2.0.34 验证记录

日期：2026-10-23，Windows x64。写回测试仅使用临时游戏镜像，真实游戏资源只读。

## 验证范围

- MOD 清单识别旧版场地／音乐记录，场地两个模型变体合为一项，三个音乐阶段分别显示；场地预览不重复出现在 MOD 列表。
- 若场地预览图本身也被独立替换，仍保留单独的图片 MOD 条目和还原入口，不与模型修改混淆。
- 导出四个 MOD 条目得到五个完整 Bundle；重新导入后修改哈希一致，首次原版备份哈希保持不变。
- 场地、音乐和图片混合批量还原逐字节一致；提交后注入失败，全部修改回滚。
- 备份导入首项提交后注入失败，目标全部回滚；不同 Build 拒绝覆盖；导入映射到另一个当前账号后仍能还原原版。
- 未知外部修改仍显示在清单中，但还原及导出均拒绝覆盖，修改字节保持不变。
- 修改场地／音乐显示黄色，原版保持普通颜色，还原后恢复普通颜色；检查 MOD 管理窗口截图。
- 既有场地替换、中文搜索、缩略图、三阶段音乐组替换、音频导入／解码、试听重复停止及四语窗口回归。
- 既有 Mod 包、MOD 管理、卡图批量还原回归。

Release x64 构建成功，365 个既有警告、0 错误。四组回归命令为 `--test-duel-resources`、`--test-mod-packages`、`--test-mod-management`、`--test-texture-mod-restore`，构建产物与完整发布目录均退出码 0；测试使用临时镜像，涉及的真实游戏文件哈希保持不变。补充独立预览图处理后，最终发布 EXE 的场地／音乐与 MOD 管理回归再次通过。测试入口选择有完整资源的账号，避免最新空账号导致只读 fixture 缺失。
